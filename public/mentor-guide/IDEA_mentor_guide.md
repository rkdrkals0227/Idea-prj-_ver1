# 배움이 일어나는 웹게임을 설계하는 법
## IDEA 멘토·멘티 실무 안내서

대학생 예비교사를 위한 수업 준비 · 교육용 프로그램 설계 · 모의수업 · 성찰

2026년 10월 26일 작성 | 협의용 실행안

> 이 안내서의 목표는 멋진 게임 하나를 만드는 데서 끝나지 않습니다. “누구의 어떤 학습 어려움을, 어떤 활동으로 바꿀 것인가”를 설명하고 실제로 시험할 수 있는 수업 한 건을 만드는 것입니다.

### 먼저 할 일, 다섯 가지

1. 교과·학년·단원을 고르고 실제 교육과정과 교과서를 펼칩니다.
2. 가상 학습자에게 예상되는 어려움을 한 가지로 좁힙니다.
3. 수업이 끝난 뒤 확인할 행동을 한 문장으로 씁니다.
4. 5~8분짜리 게임 한 판과 두 가지 지원 경로를 설계합니다.
5. 동료의 실제 플레이를 관찰하고, 가장 중요한 문제 한 가지를 고칩니다.

### 이 문서의 사용법

- 2~6쪽: IDEA 단계별 방법과 작성 칸입니다. 멘티가 먼저 쓰고 멘토가 질문합니다.
- 7~10쪽: 「금산마을 탐험대」 사례, 한 차시 지도안, 네 번의 멘토링, AI 요청 예시입니다.
- 11~16쪽: 검증·포트폴리오·확장 운영·활동지·자료 안내입니다.

기본 산출물은 **개인 포트폴리오 1건**입니다. 사례집·캠프·논문·제품 아이디어는 같은 수업 설계를 바탕으로 이어갈 수 있지만, 별도 확정·동의·검토가 필요한 확장입니다.

### 멘티에게 드리는 약속

코딩을 잘하는 사람이 유리한 과제로 만들지 않습니다. 적절한 목표를 세우고, AI의 초안을 검토하고, 학생의 반응에 근거해 고친 흔적을 남기는 것이 중요합니다. 3D는 선택이며, 작은 2D 게임도 충분한 수업자료가 될 수 있습니다.

## 2. IDEA의 전체 구조와 운영 기준

**Investigate 분석 → Design 설계 → Execute 적용 → Assess 성찰**

IDEA는 이 사업의 수업 설계와 멘토링을 묶는 운영 틀로 사용합니다. 이 문서만으로 새로운 교수설계 모형의 독창성이나 효과가 검증되었다고 주장하지 않습니다. 논문에서는 관련 선행연구와 기존 모형을 별도로 검토합니다.

| 단계 | 반드시 답할 질문 | 남길 핵심 증거 |
| --- | --- | --- |
| I · Investigate | 누구에게 무엇이 어렵고, 왜 도와야 하나요? | 학습자 분석과 학습 문제 |
| D · Design | 어떤 행동이 목표를 연습하게 하나요? | AI 활용 지도안과 게임 설계 |
| E · Execute | 실제로 실행하면 어디서 막히나요? | AI 활용 수업자료와 관찰 기록 |
| A · Assess | 무엇이 나아졌고, 무엇을 다시 고치나요? | 모의수업 성찰과 수정 전후 |

### 계획에서 확인된 기준과 아직 정할 사항

| 구분 | 적용 원칙 |
| --- | --- |
| 기본 참여 구조 | 첨부 협의자료 기준: 현직 초등교사 2명, 대학생 멘티 10명, 멘토당 5명 |
| 개인 필수 산출물 | 학습자 분석 + AI 활용 지도안 1차시 이상 + AI 활용 수업자료 + 모의수업 성찰 |
| 완성 인정 | 필수 4종 제출과 기존 평가기준 총점 60점 이상. 이 안내서는 별도 점수를 신설하지 않음 |
| 게임 공통 범위 | 설치·로그인 없는 1종, 한 차시 안의 5~8분 활동, 두 지원 경로, 설명형 피드백, 다시 시작 |
| 확장 구상 | 메모의 11명·10교과+창체, 출판·캠프·논문·제품화는 확정된 기본 의무와 구분 |

멘토는 교육과정·학년 적합성·안전·교실 사용성을 점검합니다. 멘티는 AI 결과를 읽고 검증하며 직접 제작·시험·수정합니다. 각 회차의 끝에는 **다음에 고칠 한 가지와 확인 방법**을 남깁니다.

## 3. I · Investigate — 학습 문제를 구체화하기

게임 장르나 캐릭터보다 학습자를 먼저 정합니다. 처음에는 실제 초등학생 개인정보 대신 가상 학습자 사례를 씁니다. 캠프 대상이 정해지면 학년과 운영 환경에 맞춰 분석을 갱신합니다.

### 멘티가 준비하고 쓰는 순서

1. 실제 적용할 교육과정·교과서의 단원과 성취기준을 확인합니다. 코드와 원문을 추측해서 만들지 않습니다.
2. “사회가 어렵다” 대신 “공공시설의 필요성을 이용자의 불편과 연결해 설명하지 못한다”처럼 어려움을 좁힙니다.
3. 예상과 근거를 구분합니다. 관찰하지 않은 것을 “학생들이 모두 못한다”고 쓰지 않습니다.
4. 목표를 관찰 가능한 행동으로 씁니다. “안다”보다 “선택하고 이유를 설명한다”가 확인하기 쉽습니다.
5. 읽기·조작·언어·기기 사용 차이에 대응할 두 지원 경로를 정합니다.

| 작성 항목 | 작성 칸 / 확인 질문 |
| --- | --- |
| 교과·학년·단원 | ____________________ |
| 성취기준 | 코드·원문·출처·확인일: ____________________ |
| 가상 학습자 | 이미 할 수 있는 것 / 어려움 / 수업 환경: ____________________ |
| 한 가지 학습 문제 | 누구의 어떤 행동에서 어려움이 예상되나요? ____________________ |
| 한 차시 목표 | 학생은 __________ 상황에서 __________하고, __________를 근거로 설명한다. |
| 배움의 증거 | 게임 선택 + 말·글·수행 중 무엇을 확인할까요? ____________________ |

### 두 지원 경로의 예

**기본 경로:** 짧은 상황을 읽고 선택한 뒤 스스로 이유를 설명합니다. **도움 경로:** 같은 목표를 유지하면서 그림 강조, 문장 나누기, 핵심 낱말, 힌트, 문장 틀을 제공합니다. 도움을 받았다는 이유로 낙인이나 순위 차이를 만들지 않습니다.

멘토 질문: “이 어려움의 근거는 무엇인가요? 게임이 없어도 확인할 수 있는 목표인가요?”

완료 확인: 목표와 성취기준의 연결, 가정과 관찰의 구분, 두 지원 경로가 적혀 있으면 D로 넘어갑니다.

## 4. D · Design — 목표와 게임의 행동을 연결하기

설계의 중심은 **학생 행동 → 판단 근거 → 설명형 피드백 → 재시도**입니다. 보상·그림·음악은 이 과정을 돕는 역할을 합니다.

| 설계 항목 | 예: 안전한 통학로 미니게임 설계안 |
| --- | --- |
| 학습 목표 | 통행을 방해하는 상황을 찾아 개선 방법을 고르고, 이용자의 어려움과 연결해 설명하기 |
| 학생 행동 | 길을 살펴보기 → 문제 선택 → 해결 방법 선택 → 이유 쓰기 |
| 판단 근거 | 정해진 조건과 근거에 따라 선택을 확인. 의견의 타당성은 교사가 확인 |
| 정답 피드백 | “길 위의 물건을 치우면 길을 찾고 이동하는 데 도움이 돼요.” |
| 오답 피드백 | “이 물건이 그대로 있으면 누구의 이동이 어려울까요? 다시 살펴보세요.” |
| 다시 하기 | 같은 상황을 다시 보거나 새 상황에 적용하기 |

### 종이에 먼저 그릴 다섯 화면

- 시작: 오늘 무엇을 연습하는지와 조작법.
- 상황: 학습에 필요한 정보와 선택 가능한 대상.
- 반응: 학생의 선택·조합·설명.
- 피드백: 결과와 이유, 오답의 힌트, 다시 시도.
- 마무리: 배운 내용을 현실의 행동이나 말로 연결.

### 설계할 때 지킬 구분

사실 문제는 정답과 출처를 갖춥니다. 의견 문제는 정답 하나를 강요하지 않고 타당한 근거를 살핍니다. 게임을 완료했다는 기록과 목표를 이해했다는 증거도 구분합니다. 단순 클릭 횟수나 성공 스탬프만으로 학습 효과를 판정하지 않습니다.

작성 칸: 목표 ______ / 핵심 행동 ______ / 정답·판단 기준 ______ / 오답 설명 ______ / 도움 경로 ______ / 수업 후 확인 질문 ______

멘토 질문: “학생이 게임을 잘하면 무엇을 잘한 것인가요? 학습 내용 없이 요령만으로 통과할 수 있나요?”

완료 확인: 지도안에 도입·게임·설명·정리·평가를 넣고, 문제·정답·해설 원고를 검토한 뒤 제작합니다.

## 5. E · Execute — 작은 버전을 만들고 수업으로 시험하기

첫 버전은 핵심 학습 행동 한 가지가 작동하면 됩니다. 3D 모델, 음악, 효과는 기본 활동이 검증된 다음에 넣습니다. AI에게 모든 기능을 한 번에 요청하기보다 한 기능씩 만들고 직접 실행합니다.

### 제작과 시험 순서

1. 시작 → 한 문제 → 판단 → 설명 → 재시도의 최소 흐름을 만듭니다.
2. 기본·도움 경로를 모두 실행하고, 정답·오답·중복 클릭을 시험합니다.
3. 새로고침·다시 시작·키보드·터치·작은 화면·소리 설정을 확인합니다.
4. 동료가 초등학생 역할로 설명을 적게 듣고 플레이하게 합니다.
5. 멘티는 관찰하고, 핵심 장면을 실제 수업처럼 발문·정리까지 진행합니다.

| 관찰 사실 | 해석은 따로 | 다음 수정 |
| --- | --- | --- |
| 예: 동료가 다음 버튼을 20초 동안 찾지 못함 | 버튼의 위치나 이름이 불명확할 수 있음 | 버튼 문구를 바꾸고 같은 과업으로 재시험 |
| 예: 성공했지만 이유 설명에서 이용자의 불편을 말하지 못함 | 선택 요령만 익혔을 가능성 | 선택 후 이유 질문과 설명 피드백 보완 |

### 관찰 활동지

시험자 코드 ______ / 날짜 ______ / 기기·브라우저 ______ / 버전 ______

맡긴 과업 ______ / 실제 행동·발언 ______ / 도움을 준 순간 ______ / 걸린 시간 ______ / 오류 재현 순서 ______ / 재시험 결과 ______

멘토 질문: “실제로 무엇을 보았나요? 추측을 빼고 말해 볼까요? 수업 목표와 관계있는 문제부터 고치고 있나요?”

동료시험은 내용·사용성 검증입니다. 실제 초등학생의 학습 효과를 실증한 결과로 쓰지 않습니다. 캠프 수업이 확정되면 대상·동의·운영 조건을 확인한 뒤 별도 적용 기록을 남깁니다.

완료 확인: 동작하는 게임 링크 또는 파일, 수업자료, 모의수업 장면, 관찰과 수정 기록이 있어야 A에서 근거를 갖고 성찰할 수 있습니다.

## 6. A · Assess — 근거로 성찰하고 다음 설계로 돌아가기

성찰은 “재미있었다”로 끝내지 않습니다. 목표·학생 행동·지원·AI 활용 중 무엇을 바꿨는지 설명하고 수정 전후 자료를 붙입니다.

### 성찰의 네 문장

1. 처음에는 __________라는 어려움을 해결하려고 했다.
2. 시험에서 실제로 __________라는 행동·발언을 관찰했다.
3. 그래서 __________를 __________로 바꾸었다. 이유는 __________이다.
4. 재시험에서는 __________를 확인했다. 아직 __________는 확인하지 못했다.

| 성찰할 대상 | 확인할 증거 |
| --- | --- |
| 목표와 활동 | 게임의 어떤 행동이 목표를 연습하게 했는가? |
| 학습 확인 | 선택 결과뿐 아니라 설명·수행에서 무엇이 드러났는가? |
| 지원의 적절성 | 도움 경로가 답을 대신 주었는가, 생각을 이어 주었는가? |
| AI 활용 | 채택·수정·폐기한 제안과 그 판단 근거는 무엇인가? |
| 교실 적용 | 시간·조작·소리·읽기·오류 대응이 수업에서 가능한가? |

### 점검 상태는 세 가지로만

**진행 가능 / 보완 필요 / 교수자·기술 지원 연결 필요.** 이 상태는 피드백용이며 공식 점수표가 아닙니다. 필수 4종과 기존 평가기준은 그대로 적용합니다.

### 12월 성찰과 1월 캠프 성찰을 구분하기

12월 21일에는 앞선 모의수업과 수정 근거를 정리합니다. 1월 캠프가 열리면 다시 E로 돌아가 실제 적용을 기록하고, 그 뒤 A 기록을 추가합니다. 아직 하지 않은 캠프를 이미 적용한 것처럼 포트폴리오에 쓰지 않습니다.

멘토 질문: “가장 중요한 수정 한 가지는 무엇이며, 왜 그것부터 고쳤나요? 다음 교사가 설명서만 보고 사용할 수 있나요?”

완료 확인: 수정 전후, 검증 결과, 남은 한계, 다음 실행 계획이 함께 있어야 합니다.

## 10. AI를 활용하는 네 가지 요청문

멘티는 AI의 답을 그대로 제출하지 않습니다. 매번 **채택 / 수정 / 폐기 + 이유 + 확인 자료**를 남깁니다. 실제 초등학생 이름·성적·사진·음성은 입력하지 않습니다.

### I — 분석 초안을 요청할 때

> [교과·학년·단원]과 내가 확인한 성취기준 [코드·원문·출처]를 바탕으로 가상 학습자의 예상 어려움 3가지를 제안해 줘. 관찰 사실로 단정하지 말고 가정으로 표시해 줘. 각 어려움에 관찰 가능한 목표와 기본·도움 경로를 연결해 줘. 확인되지 않은 성취기준이나 출처는 만들지 마.

검토할 것: 학년 적합성, 기준의 실제 존재, 목표가 한 차시에서 가능한지.

### D — 게임의 학습 행동을 설계할 때

> 목표는 [목표]야. 5~8분 활동의 시작·상황·반응·피드백·마무리 화면을 설계해 줘. 각 화면에 학생 행동과 학습 증거를 적어 줘. 사실 문제와 의견 질문을 구분하고, 오답에는 이유와 재시도 힌트를 제공해 줘. 기능은 핵심 흐름에 필요한 것만 제안해 줘.

검토할 것: 목표와 무관한 장식·기능, 아무 선택이나 성공하는 판정, 도움 경로의 답 노출.

### E — 한 기능을 구현·수정할 때

> 현재 파일 구조는 [구조], 실행 방법은 [명령]이야. [한 기능]만 수정해 줘. 성공·오답·중복 입력·다시 시작의 예상 동작을 먼저 적고 실제 실행해 줘. 입력 중 이동을 멈추고, 오류가 나도 복구 안내가 나오게 해 줘. 실행하지 못한 검사는 구분해서 보고해 줘.

검토할 것: 실제 실행 여부, 존재하지 않는 파일·연결의 주장, 개인정보·외부 전송.

### A — 기록을 바탕으로 성찰할 때

> 아래는 익명화한 관찰 기록 [기록]과 수정 전후 [변경]야. 관찰 사실·내 해석·다음 수정으로 나눠 정리해 줘. 기록에 없는 성과나 학생 반응을 추가하지 마. 동료시험을 초등학생 학습 효과로 바꾸어 쓰지 마. 내가 확인하지 못한 부분도 남겨 줘.

검토할 것: 미화된 효과 주장, 인과관계의 과장, 기록에 없는 발언·숫자.

### 자료와 개인정보의 원칙

전설은 전해지는 이야기로, 생태 관찰은 조사 시점의 기록으로 표시합니다. 현재 서식 수나 지명 유래를 근거 없이 단정하지 않습니다. 점자블록·야생생물 활동은 실제 수리·포획을 권하는 행동이 되지 않게 합니다.

초등학생의 AI 조작은 서비스 약관·연령·계정 정책을 확인하기 전에는 계획하지 않습니다. 기본안은 예비교사가 AI를 사용해 검토한 자료를 만들고, 초등학생은 그 자료로 학습하는 방식입니다. AI 서비스별 최신 약관은 적용 시점에 확인합니다.

실제 캠프의 참가, 개인정보, 사진·영상, 연구, 외부 공개는 목적과 범위를 구분해 필요한 동의와 기관 절차를 확인합니다. 학생 자료를 AI 서비스에 임의로 올리거나 공개 링크에 넣지 않습니다. 웹게임은 외부 요청과 저장 위치를 사용 설명서에 적습니다.

공개 적합성 검수는 포트폴리오 통과와 별개입니다. 누가 자료를 유지·수정·삭제할지도 정합니다.

『지금부터 시작하는 AI 교수법』은 메모에서 제시한 가제입니다. 제목 중복·저자 구성·기관명 사용·출판 일정은 별도 확인합니다. 비매품 사례집과 정식 출판은 확정된 제출 의무로 표시하지 않습니다.

메모의 1월 중순 2~3일 캠프와 1월 21일 특강 연결은 운영 제안입니다. 대상 학년·인원·장소·기기·보호자 안내·보조 인력·긴급 대응·촬영 여부를 확정한 후 지도안을 조정합니다. 12월 성찰 뒤 1월 적용, 그 뒤 성찰 보완의 순서로 기록합니다.

### 연구는 운영 기록과 구분

연구 활용 동의와 기관의 IRB 심의·면제 절차를 먼저 확인합니다. 사전검사는 참여 전 측정이어야 합니다. 이미 시작한 뒤의 자료를 날짜를 바꿔 사전검사로 만들지 않습니다. 메모의 AI·디지털 역량 5문항은 원문·출처·사용 조건을 확보한 뒤 같은 문항·척도로 비교합니다.

소규모 사전·사후 변화와 성찰 자료는 프로그램의 가능성과 한계를 보여 주는 자료입니다. 비교 집단이나 추가 근거 없이 프로그램 때문에 효과가 생겼다고 단정하지 않습니다. 동료 모의수업과 실제 초등학생 적용 결과도 구분합니다.

다음은 작은 게임의 작성 예시입니다. 성취기준과 실제 대상은 확정 전이므로 교사 검토 후 바꿉니다. 현재 게임의 추가 구현 완료를 뜻하지 않습니다.

| 항목 | 작성 예시 |

| 임시 제목 | 길을 막지 않는 선택 |

| D · 한 판의 행동 | 길 그림 살펴보기 → 방해물 찾기 → 해결 방법 선택 → 이유 설명 → 새 그림 재도전 |

| D · 도움 경로 | 그림 강조 + “___에게 ___이 어려워요” 문장 틀. 기본 경로는 스스로 설명 |
| E · 최소 구현 | 상황 2개, 선택 3개씩, 정오답 이유, 재시도, 다시 시작, 키보드·터치 |

| A · 수정 기준 | 이용자의 불편을 설명하지 못하면 상황 정보·피드백·발문을 먼저 고침 |
