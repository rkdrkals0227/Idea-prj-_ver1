# 업로드 모델 연결

2026-10-25: 첨부 30개 중 18개를 받았습니다. 받은 파일의 원본 이름, 최적화 용량, 실제 클립 이름은 `public/models/uploaded/provenance.json`에 기록했습니다. 원본 업로드 파일은 수정하지 않습니다.

## 연결 현황

| 역할 | 사용 파일/동작 |
|---|---|
| turtle | 남생이 정지, 걷기 Walking, 인사 Big_Wave_Hello |
| crane | 학 인사 파일의 Idle_15 대기, 걷기 파일의 Walking, 인사 Big_Wave_Hello |
| lamp / bench / sign | 가로등, 벤치, 안내 표지판. 표지판 앞면에 장소 이름을 별도 텍스처로 표시 |
| wastePaper / wasteBottle / wasteCan | 기존 수거 물체 ID에 연결, 수거하면 사라짐 |
| wasteWrapper | 안내 길의 방해물. 장애물 정리/길 수리를 완료하면 사라짐 |
| tactile / tactileBroken | 연결 경로와 파손 위치. 수리 전후 정상 타일로 교체 |
| paving / grass / water / lotusWater | 보도, 풀밭, 남강과 금호지의 수면. 반복 타일은 InstancedMesh로 배치 |

다음 **12개는 32MiB 전송 한도를 초과하여 다운로드하지 못했습니다.** 주인공 정지/걷기, 수달 정지/걷기/인사, 학 정지, 학교, 도서관, 아파트 단지, 연못, 나무, 울타리. 사용자가 크기를 줄여 다시 제공할 예정이며 연결 완료로 표시하지 않습니다. 주인공·수달·건물·나무는 기존 임시 모형을 유지합니다. 울타리 전용 모델도 아직 설치하지 않았습니다. 학 정지 원본 대신 받은 인사 파일의 실제 대기 클립을 사용합니다.

## 설정과 다음 파일 연결

1. GLB를 `public/models/` 아래에 넣습니다. glTF는 `.bin`·텍스처도 상대 경로대로 함께 넣습니다.
2. `src/data/asset-manifest.json`에서 역할 ID의 `url`을 public 기준 상대 경로로 설정합니다.
3. `variants.idle/walk/greet`에 각 파일의 `url`, 실제 애니메이션 `clip`을 설정합니다. 한 파일에 모두 있으면 같은 URL을 재사용해도 한 번만 요청합니다. 옛 `animations.idle/walk` 설정도 지원합니다.
4. 캐릭터 `targetHeight`는 발부터 머리까지 높이입니다. `targetSize`는 가장 긴 변, `fit: [너비, 높이, 깊이]`는 바닥/표지판처럼 지정한 공간에 맞추는 비율입니다. 중심 X/Z와 바닥 Y를 정규화하고 `rotation`(Y축 라디안), `groundHeight`를 적용합니다.
5. 건물 `position`과 `collision`은 기존 동선/출입 위치입니다. 새 건물이 이 영역에 들어오도록 크기·방향을 확인하고 실제 문 앞에서 E로 출입을 검증합니다. 표지판은 건물과 독립되어 유지됩니다.
6. 대화·퀘스트·작품·저장 ID는 바꾸지 않습니다. 파일/리소스 실패 시 해당 모형은 임시 모형으로 돌아갑니다. 캐릭터는 일부 상태 파일만 실패해도 모형이 겹치지 않게 전환합니다.

받은 동물은 대기, 아주 짧은 제자리 주변 걷기, 상호작용 시 한 번 인사를 합니다. 걷는 동안에도 상호작용 기준점에서 0.35 이내로 유지합니다. 움직임 줄이기를 켜면 순찰과 대기 움직임을 멈추며 인사만 한 번 보여 줍니다. 동물 머리 위 이름표는 없고 첫 대화 소개를 유지합니다.

## 웹 사본 만들기

텍스처를 최대 512px로 축소하고 정적 메시의 면 수를 제한했습니다. 반복 바닥은 약 500삼각형, 다른 정적 소품은 약 2,500삼각형입니다. 애니메이션 파일은 스킨·애니메이션 버퍼를 유지하고 텍스처만 줄였습니다. 압축으로 세밀한 표면 표현이 줄어들 수 있습니다.

Blender 4.3.2와 Python Pillow를 사용했습니다. 재처리 작업 목록 JSON은 `[{"name":"turtle-walk","path":"원본.glb","animated":true}]` 형식이며 다음을 실행합니다.

```bash
blender -b -t 2 --python scripts/prepare-models.py -- /path/to/jobs.json
```

브라우저에서의 초기 준비 상태와 실패를 표시하며, 동일 파일은 캐시하고 반복 바닥은 공유합니다. 실제 교실 노트북 FPS·Safari·태블릿 검증은 남아 있습니다. 낮은 화질은 그림자와 화면 해상도를 낮춥니다.

## 같은 날 두 번째 첨부 파일로 교체

`*_place_*.glb` 등의 영문 파일명으로 다시 받은 파일 중 **13개 소품/바닥**을 다시 최적화하여 같은 역할 경로에 덮어썼습니다. 기존 남생이·학 파일 5개는 그대로 유지합니다. `provenance.json`은 이번에 바꾸지 않은 파일 기록도 유지합니다.

학교 45,436,656바이트, 도서관 53,402,680바이트, 아파트 74,472,612바이트, 연못 50,091,120바이트, 나무 60,188,292바이트, 울타리 36,932,736바이트는 첨부된 용량 비교표 기준으로 여전히 32MiB 전송 한도를 넘으며 다운로드 도구도 이를 거부했습니다. 이 6개의 실제 메시/텍스처는 읽지 못해 연결하지 않았습니다. 비교표는 `docs/model-size-comparison.csv`에 보관합니다. 표에 적힌 주인공·수달·학 정지 파일은 이번 첨부 목록에 없으므로 실제 모델을 확인한 것으로 보지 않습니다.

파일을 더 줄이기 어렵다면 원본 GLB를 여러 조각으로 나눠 첨부해도 됩니다. Mac의 기본 `split` 명령은 설치 없이 동작하며 원본을 바꾸지 않습니다. 예를 들어 다운로드 폴더에 있는 학교 파일은 다음과 같이 나눕니다.

```bash
cd ~/Downloads
split -b 25m 05_place_school.glb school.part-
```

생긴 `school.part-aa`, `school.part-ab` 등의 조각을 모두 전달하면 순서대로 합쳐 처리할 수 있습니다. 압축 ZIP 자체가 30MB 이하라면 분할 없이 ZIP을 전달해도 됩니다. 파일 경로에 공백이 있으면 따옴표로 감쌉니다.
